# Техническое задание

## Проект

Система перевода текста на экране в режиме реального времени для Windows 11 с наложением перевода поверх оригинального текста в компьютерных играх.

------------------------------------------------------------------------

# 1. Назначение системы

Приложение предназначено для автоматического распознавания текста в заданных областях экрана, перевода текста через онлайн-сервисы перевода и отображения перевода непосредственно поверх оригинального текста.

Основной сценарий использования:
- запуск игры;
- выбор или загрузка профиля игры;
- автоматическое распознавание субтитров и другого игрового текста;
- перевод текста;
- скрытие оригинального текста (сплошная заливка или затемнение);
- отображение перевода на месте оригинала.

------------------------------------------------------------------------

# 2. Ограничения проекта

## Поддерживаемые платформы
- Windows 11 x64

## Не входят в проект
- Linux, macOS, Android, iOS
- работа с несколькими мониторами
- облачная синхронизация
- собственный сервер перевода
- встроенные платные переводчики разработчика
- хранение API-ключей разработчика

## Поддержка игр
Обязательно: оконный режим, borderless fullscreen.
Желательно: exclusive fullscreen (отсутствие поддержки в отдельных играх не считается ошибкой).

Взаимодействие с игрой ограничено screen capture выбранных областей. Память игры, injection, hooks, drivers и anti-cheat bypass не входят в продукт и запрещены.

## Минимальные требования к железу
- CPU: 6 ядер / 12 потоков (не старее 2020 года)
- RAM: 8 ГБ
- GPU: любая с поддержкой DirectX 11

------------------------------------------------------------------------

# 3. Основные функции

## Захват изображения
- захват только внутри настроенных OCR-зон;
- поддержка нескольких независимых OCR-зон одновременно.

## OCR
- распознавание текста в реальном времени;
- поддержка нескольких текстовых блоков внутри одной OCR-зоны;
- получение координат и размеров каждого текстового блока;
- обновление координат при перемещении текста.

Штатный путь по ADR-030 внутри каждой вручную сохранённой OCR-зоны: GPU Paddle detector → bounded deterministic grouping → Tesseract recognition отдельных crop → выбранный переводчик → overlay по регионам. Paddle предлагает только transient bounds и не является recognizer. При недоступности detector/runtime пользователь получает контролируемое degraded-состояние; legacy full-page OCR, full-frame retry, другой provider или cache не выбираются автоматически.

По ADR-031 каждая сохранённая OCR-зона имеет `ContentLayoutMode`. Начальное и текущее значение `DialogComic` объединяет штатную bounded writing-system grouping policy, centered per-region overlay и участие зоны в каждом live refresh. Язык и orientation по-прежнему автоматически выбирают частный writing-system grouping profile внутри режима. Новые `Book`, `StaticMenu`, ненулевая частота обновления или иная overlay policy требуют отдельного решения и измеримых регрессий; режим не может включать legacy/full-frame/provider fallback.

## Перевод
Поддерживаемые сервисы: Google Translate API, Microsoft Azure Translator, Яндекс Переводчик API. Архитектура позволяет добавление новых переводчиков.

## Использование API
Приложение не содержит встроенных API-ключей. Пользователь самостоятельно вводит API Key, Secret Key, Endpoint, Region и иные параметры.

------------------------------------------------------------------------

# 4. Хранение учетных данных

API-ключи хранятся только в защищенном хранилище Windows (Windows Credential Manager или DPAPI). Запрещено хранение в JSON, INI, XML, а также экспорт вместе с профилями.

------------------------------------------------------------------------

# 5. OCR-зоны

Профиль игры может содержать любое количество OCR-зон. Каждая зона хранит абсолютные координаты (X, Y, Width, Height) и относительные (X%, Y%, Width%, Height%). При изменении разрешения экрана зоны автоматически пересчитываются. Пересечение OCR-зон запрещено – при обнаружении пересечения профиль не сохраняется.

------------------------------------------------------------------------

# 6. Поддержка языков

Минимальный набор: английский, русский, украинский, японский, китайский упрощенный, китайский традиционный, корейский. Архитектура поддерживает расширение списка.

------------------------------------------------------------------------

# 7. Поддержка вертикального текста

## Японский язык
Поддерживать Yokogaki (горизонтальное) и Tategaki (вертикальное). Режимы: Auto, Horizontal, Vertical.

## Китайский язык
Поддерживать горизонтальный и вертикальный текст, традиционные и упрощенные иероглифы.

**Важно:** Tesseract OCR является обязательным recognizer для вертикального текста и для каждого принятого candidate crop. Windows OCR и Tesseract остаются поддерживаемыми OCR-движками. GPU Paddle detector уже разрешён ADR-030 исключительно как provider transient bounds; новый recognizer или смена этих границ требует отдельного ADR.

------------------------------------------------------------------------

# 8. Замена оригинального текста

Используется режим полной замены. После распознавания приложение обязано скрыть оригинальный текст (сплошная заливка цветом или затемнение с настраиваемой непрозрачностью) и отобразить перевод поверх оригинала. Оригинальный текст не должен быть читаем пользователем.

------------------------------------------------------------------------

# 9. Система слоев

Для каждого текстового блока: Слой 1 – OCR Block, Слой 2 – Mask Layer (Solid или Darken), Слой 3 – Translation Layer, Слой 4 – Debug Layer (только в режиме отладки).

------------------------------------------------------------------------

# 10. Семантические группы и отображение перевода

Raw OCR-блоки сохраняются для диагностики и маскирования. Pipeline может объединять близкие raw-блоки в semantic translation group для диалога, меню или комикса, сохраняя детерминированный reading order и исходные member bounds.

Mask bounds остаются привязанными к raw/semantic OCR source. Translation text bounds могут отличаться от mask bounds, если это требуется для читаемости и не нарушает правила overlay. Для vertical OCR применяется ADR-016: controlled wrap width, рост текста по высоте и только затем уменьшение шрифта.

После стабилизации source region semantic translation groups обрабатываются и доставляются независимо. Готовый перевод одного региона должен появляться в overlay без ожидания OCR, перевода или layout других регионов того же кадра. При смене изображения отменяются только задачи региона, чей source identity изменился или исчез; результаты неизменённых регионов остаются допустимыми. Это не меняет сохранённые OCR-зоны профиля: transient candidate regions существуют только внутри текущей зоны захвата согласно ADR-030. Legacy full-page orchestration остаётся только явным diagnostic/compatibility режимом.

------------------------------------------------------------------------

# 11. Настройка внешнего вида

Пользователь может изменять: шрифт, размер, жирность, курсив, цвет текста, цвет обводки, толщину обводки, прозрачность, межстрочный интервал, внутренние отступы. Система автоматически переносит длинные строки, не обрезая текст.

------------------------------------------------------------------------

# 12. Маска скрытия текста

Настраиваемые параметры: тип (сплошная заливка или затемнение), цвет, непрозрачность, внутренние отступы. Solid и Darken являются поддерживаемыми MVP-режимами. Blur не является текущим режимом продукта; AI/content-aware реконструкция игрового изображения запрещена.

------------------------------------------------------------------------

# 13. Кэш переводов

Кэш обязателен. Если ранее уже переводился идентичный текст, перевод берется из кэша. Кэш сохраняется между запусками. Отдельный кэш для каждой языковой пары. TTL кэша – 30 дней (по умолчанию), возможность ручной очистки.

------------------------------------------------------------------------

# 14. Производительность

Система должна сравнивать кадры, выполнять OCR и перевод только при изменениях, минимизировать нагрузку на CPU и GPU. Целевые показатели: OCR цикл ≤ 200 мс (MVP), средняя загрузка CPU ≤ 25%, пики до 50% на рекомендованном железе.

------------------------------------------------------------------------

# 15. Настраиваемый OCR

Параметры: яркость, контрастность, резкость, шумоподавление, бинаризация, масштабирование. Фильтрация: минимальный/максимальный размер текста, минимальная длина строки, игнорирование цифр/символов (все фильтры отключаемы).

------------------------------------------------------------------------

# 16. Профили игр

Каждая игра может иметь собственный профиль. Параметры: название, описание, список OCR-зон, настройки OCR, отображения, перевода, горячие клавиши, язык оригинала, язык перевода, используемый переводчик.

------------------------------------------------------------------------

# 17. Импорт и экспорт

Формат JSON. Экспортируются настройки OCR, интерфейса, OCR-зоны, настройки отображения, переводчика. API-ключи и учетные данные не экспортируются.

------------------------------------------------------------------------

# 18. Горячие клавиши

По умолчанию: Ctrl+Shift+F1 – Старт/Пауза OCR, Ctrl+Shift+F2 – Показать/Скрыть перевод, Ctrl+Shift+F3 – Выбор OCR-зоны, Ctrl+Shift+F4 – Настройки, Ctrl+Shift+F12 – Выход. Все клавиши переназначаются пользователем.

------------------------------------------------------------------------

# 19. Режим отладки

Отображать: OCR-зоны, границы OCR-блоков, координаты, распознанный и переведенный текст. Метрики: OCR latency, Translation latency, Render latency, FPS, CPU usage, Memory usage. Статистика: Cache Hit, Cache Miss, OCR Count, Translation Count.

------------------------------------------------------------------------

# 20. Проверка профилей

Перед сохранением проверять пересечение зон, выход за границы экрана, корректность координат, выбранный переводчик, языки. При ошибке сохранение запрещается.

------------------------------------------------------------------------

# 21. Архитектура модулей

Модуль профилей, захвата экрана, OCR, анализа текста, перевода, кэширования, отображения (overlay), горячих клавиш, настроек, отладки, хранения учетных данных. Все модули максимально независимы.

------------------------------------------------------------------------

# 22. Требования к расширяемости

Архитектура должна позволять без переработки ядра: добавление новых OCR-движков, переводчиков, языков, типов профилей, модернизацию алгоритмов позиционирования.

------------------------------------------------------------------------

# 23. MVP

Первая версия считается завершенной при наличии: многозонного OCR, перевода через Google, Azure, Яндекс, профилей игр, импорта/экспорта JSON, кэша переводов (TTL 30 дней), горячих клавиш, режима отладки, замены оригинального текста (маска solid/darken), поддержки горизонтального и вертикального текста (через Tesseract), работы в оконном и borderless fullscreen режимах Windows 11, автообновления (Squirrel/SingleFilePublisher).

------------------------------------------------------------------------

# 24. Пользовательский интерфейс (MVP)

- Одно окно с возможностью сворачивания панелей (Expander).
- Главная кнопка: зеленая «Запустить перевод» / красная «Остановить перевод».
- Добавление OCR-зон выделением области мышью (аналог «Ножниц»).
- Выбор языка оригинала, целевого языка, типа переводчика.
- Регулировка частоты обновления (FPS).
- Понятные статусы recoverable ошибок OCR, language pack, capture, provider и overlay без раскрытия секретов.
- Журнал ошибок с возможностью очистки.
