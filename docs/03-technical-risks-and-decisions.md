# Технические риски и спорные решения

## Проект

Система экранного OCR-перевода игровых субтитров и текста для Windows 11

Версия документа: 1.1 (обновлено)

------------------------------------------------------------------------

# 1. Назначение документа

Фиксация технических рисков, ограничений платформы, принятых архитектурных решений, которые запрещено менять без согласования.

------------------------------------------------------------------------

# 2. Общий принцип

Приоритет: стабильность, совместимость, минимальная нагрузка, простота поддержки. При конфликте красивой архитектуры и совместимости выбирается совместимость.

------------------------------------------------------------------------

# 3. Риск точности OCR игровых текстов

**Решение:** многоступенчатая система: предобработка → Windows OCR → Tesseract → сравнение результатов → кэширование. Запрещено использовать единственный OCR-движок.

------------------------------------------------------------------------

# 4. Риск вертикального японского/китайского текста

**Решение:** для вертикального текста используется только Tesseract OCR. Ввести Orientation Detector (Auto/Horizontal/Vertical). В MVP допускается ручное переключение режима пользователем.

------------------------------------------------------------------------

# 5. Риск overlay поверх игр

**Решение:** основная цель – оконный режим и borderless fullscreen. Exclusive fullscreen не гарантируется. Запрещено использовать DLL Injection, Memory Reading, Memory Injection.

------------------------------------------------------------------------

# 6. Риск античитов

Программа работает как обычное приложение, не внедряется в процесс игры, не изменяет и не читает память игры.

------------------------------------------------------------------------

# 7. Риск высокой нагрузки на CPU

**Решение:** Frame Difference Detection, OCR только при изменении кадра, кэширование результатов. Пересмотренные целевые показатели: средний CPU ≤ 25%, пики до 50% на современном железе (6+ ядер).

------------------------------------------------------------------------

# 8. Риск перегрузки переводчиков

**Решение:** многоуровневый кэш (память + SQLite) с TTL 30 дней. Запрещено повторно переводить идентичный текст без проверки кэша.

------------------------------------------------------------------------

# 9. Риск неправильного позиционирования текста

**Решение:** привязка перевода к bounding box исходного OCR-блока. Запрещено объединять текст разных OCR-блоков.

------------------------------------------------------------------------

# 10. Риск масштабирования разрешений

Хранение абсолютных и относительных координат. Приоритет относительных координат при изменении разрешения.

------------------------------------------------------------------------

# 11. Риск пересечения OCR-зон

Перекрытие запрещено. Проверка при сохранении профиля. Профиль не сохраняется при пересечении.

------------------------------------------------------------------------

# 12. Риск повреждения профилей

Обязательная валидация структуры, версии, типов данных, координат.

------------------------------------------------------------------------

# 13. Риск утечки API-ключей

Ключи хранятся только в Windows Credential Manager. Запрещено хранение в JSON, INI, XML, SQLite, логах.

------------------------------------------------------------------------

# 14. Спорное решение №1: выбор OCR

Почему не только Tesseract? Windows OCR быстрее для горизонтальных текстов. Принято: основной – Windows OCR, резервный – Tesseract, будущее – PaddleOCR.

------------------------------------------------------------------------

# 15. Спорное решение №2: выбор языка

Почему не Python? Слабая интеграция с Windows, сложность overlay, нагрузка. Решение: C# + .NET.

------------------------------------------------------------------------

# 16. Спорное решение №3: выбор базы данных

SQLite (не требует сервера, надежна, быстра). PostgreSQL/MySQL/MongoDB избыточны.

------------------------------------------------------------------------

# 17. Спорное решение №4: поддержка нескольких мониторов

Исключена из MVP (усложнение координат и overlay). Будущая версия.

------------------------------------------------------------------------

# 18. Спорное решение №5: автоматическое определение зон

Отказано из-за низкой надежности. Решение: ручная настройка зон.

------------------------------------------------------------------------

# 19. Неизменяемые архитектурные решения

Без отдельного согласования запрещено менять:
1. Язык C#.
2. UI: WPF (вместо WinUI 3).
3. Windows Graphics Capture.
4. SQLite.
5. JSON-профили (версия 1.0).
6. Windows Credential Manager.
7. MVVM.
8. Многозонный OCR.
9. Запрет перекрытия OCR-зон.
10. Отдельный Overlay-процесс.
11. Отсутствие внедрения в память игры.
12. Отсутствие DLL Injection.
13. Поддержку нескольких OCR-движков.
14. Поддержку нескольких переводчиков.
15. Кэш переводов (TTL 30 дней).
16. Маскирование без blur (solid/darken).
17. Использование Tesseract для вертикального текста.

------------------------------------------------------------------------

# 20. Критерий успеха проекта

- Перевод появляется менее чем за 500 мс после появления текста.
- Корректная замена оригинала.
- Приемлемая нагрузка на CPU (средняя ≤25%).
- Работа большинства современных игр в оконном и borderless fullscreen режимах.
- Обмен профилями через JSON без передачи API-ключей.
------------------------------------------------------------------------

# Sprint 26 Risk Addendum: Vertical CJK OCR and Overlay Placement

This addendum is current as of 2026-06-30 and applies to #32.

Risk: Tesseract vertical OCR can return many small blocks or false positives from UI chrome, halftone texture, faces, clothing, and frame art.

Decision:

- Keep Tesseract as the only OCR engine for vertical CJK.
- Keep OCR, grouping, translation, masking, and overlay placement as separate responsibilities.
- Allow semantic grouping for translation when OCR returns per-glyph or per-column fragments.
- Use raw accepted OCR blocks for masks so rejected OCR noise does not create black bars.
- Prefer conservative grouping: avoid false overlays on art even if some marginal text is missed.

Known tradeoff:

- This does not replace OCR with image understanding.
- Manual smoke diagnostics remain required for manga pages.
- If a future change requires image segmentation, a new architecture decision and approval are required before implementation.
