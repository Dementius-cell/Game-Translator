# Руководство пользователя Game Translator

Статус: актуально для исходного кода на 2026-10-15; наличие изменений в опубликованном portable зависит от его версии.

## 1. Что делает приложение

Game Translator захватывает только выбранные пользователем области экрана, находит в них текст, распознаёт его, переводит через выбранного провайдера и показывает перевод поверх исходного текста. Приложение не читает память игры, не внедряется в процесс и не обходит античит.

Штатная цепочка обработки: сохранённая OCR-зона → GPU Paddle detector → ограниченная группировка по системе письма → Tesseract для каждого принятого фрагмента → выбранный переводчик → отдельный overlay для каждого региона. Если detector/runtime недоступен, приложение показывает диагностируемое degraded-состояние и не подменяет результат скрытым full-page OCR, кэшем или другим провайдером.

Кнопка **О приложении** внизу боковой панели показывает версию запущенной сборки, видеоадаптеры Windows и ссылку на GitHub проекта. Список адаптеров не является проверкой готовности Paddle/CUDA.

Карточки разделов выровнены по левому краю. В **Зоны захвата** нажмите заголовок **Схема экрана**, чтобы свернуть или развернуть превью. Координаты превью учитывают разрешение, сохранённое в абсолютных и относительных границах зоны; перемещение и изменение размера сохраняют этот масштаб.

**Создать баг-репорт** в разделе **Диагностика и отчёты** сохраняет текстовый файл в `Reports` рядом с запущенным приложением. Жёлтая плашка показывает результат и полный путь; **Показать файл** выделяет отчёт в Проводнике. Файлы остаются локально, автоматической отправки нет. Если папка приложения недоступна для записи, используется **%LOCALAPPDATA%\GameTranslator\Reports** (локальная папка, создаваемая при запуске), и интерфейс явно сообщает об этом.

Необработанная ошибка сохраняет отдельный crash-report. При следующем запуске приложение показывает уведомление об отчёте. Если процесс был принудительно закрыт, произошёл нативный сбой или пропало питание, отчёт создаётся после перезапуска и отмечает причину как неизвестную. Работающий параллельный экземпляр не считается упавшим. Это диагностический отчёт, а не дамп памяти: он содержит версию, окружение, безопасное состояние интерфейса (для ручного отчёта), типы исключений и имена методов в стеке (когда они доступны), без ключей, содержимого исключений, сырых логов, скриншотов и OCR/переведённых текстов. Если недоступны обе папки или закончилось место, интерфейс сообщает об ошибке сохранения; crash-report при таких условиях не гарантирован.

## 2. Требования и текущая доступность

- Windows 11 x64.
- Для штатного candidate pipeline — совместимая NVIDIA GPU и полностью упакованный Paddle runtime.
- Интернет нужен переводчику и для установки отсутствующих Tesseract packs; уже установленные компоненты и локальный кэш работают без повторной загрузки.
- Официальным Google, Azure и Yandex нужны учётные данные соответствующего сервиса.

На GitHub пока нет опубликованного пакета, эквивалентного текущему `main`. Локальный распакованный portable r44 собран из текущего исходного кода и прошёл проверки Tesseract, Paddle и полного SHA-256 manifest, но у него нет transfer archive, подписи и одобрения на публикацию. Для обычной установки следует использовать только явно одобренный Release/RC с опубликованной контрольной суммой. Разработчики могут собрать проверяемый self-contained пакет по инструкции в корневом [README](../README.md).

## 3. Установка portable/RC

1. Скачайте одобренный архив и опубликованную SHA-256 только со страницы [Releases](https://github.com/Dementius-cell/Game-Translator/releases) проекта.
2. Сверьте контрольную сумму и распакуйте архив в новую отдельную папку. Не накладывайте файлы поверх предыдущей версии.
3. Запустите **app\GameTranslator.UI.exe**.
4. Не удаляйте `candidate-detector`, `tessdata`, `x64` или `x86` внутри пакета: они входят в рабочий runtime.
5. Для отката закройте приложение и запустите предыдущую проверенную версию из её отдельной папки. Профили имеют совместимую схему `1.0` и хранятся вне portable-каталога.

Portable-сборка не является Squirrel-установкой, поэтому встроенная проверка обновлений может сообщить, что установка не обнаружена. Это ожидаемо. Автообновление применяется только к соответствующим установленным пакетам.

### Навигация интерфейса

Язык интерфейса выбирается при запуске по языку интерфейса Windows: русский для русского языка системы, английский для остальных. Язык OCR и язык перевода настраиваются отдельно; имена профилей, зон и распознанный текст не локализуются.

В **Настройки приложения → Оформление приложения** доступны **Как в Windows**, **Светлая** и **Тёмная** темы. По умолчанию выбрано **Как в Windows**: редактор подхватывает цвет приложений Windows при запуске и меняется вслед за ним без перезапуска. Ручной выбор сохраняется автоматически и действует до возврата к системному режиму. Тема распространяется на редактор и окно «О приложении»; цвета перевода поверх игры по-прежнему задаются профилем.

Слева — профили; внизу боковой панели — **Настройки приложения**, **Диагностика и отчёты**, **О приложении**. Кнопка **К профилю** возвращает из общих разделов к зонам выбранного профиля.

У профиля четыре вкладки: **Зоны захвата**, **Распознавание**, **Перевод**, **Оформление**. На странице зон рядом со схемой экрана расположен компактный редактор; в узком окне он перемещается под превью. Список зон выбирает редактируемую область. **Дополнительные параметры зоны** раскрывают язык OCR, группировку и полные настройки шрифта. Схема экрана сворачивается независимо от этих параметров.

Изменения сохраняются кнопкой **Сохранить**. Надпись о готовности профиля означает корректность его параметров, а не успешную проверку GPU или сетевого переводчика.

## 4. Первый запуск

При первом запуске открывается семишаговый русский тур. Он только переключает вкладки и подсвечивает элементы: сам не создаёт профиль, не начинает захват и не обращается к переводчику. Тур можно повторить кнопкой `? Тур` в заголовке или из `Настройки приложения`.

Безопасная последовательность настройки:

1. Нажмите `Новый`, задайте имя профиля и при необходимости описание.
2. На вкладке `Перевод` выберите provider, исходный и целевой языки.
3. Для официального провайдера сохраните и проверьте credentials.
4. На вкладке `Зоны захвата` нажмите `Выделить на экране` и выделите область, где появляется текст. Для разных постоянных областей создайте отдельные непересекающиеся зоны.
5. На вкладке `Распознавание` выберите движок и направление текста; язык отдельной зоны доступен в её дополнительных параметрах. Затем нажмите `Проверить язык OCR`.
6. Если статус — `Missing`, нажмите `Установить язык OCR`, дождитесь завершения и повторите проверку.
7. Проверьте внешний вид через `Показать тестовый перевод`, сохраните профиль и только затем нажмите `Начать перевод`.

## 5. Безопасные настройки по умолчанию

| Настройка | Начальное значение | Почему безопасно |
| --- | --- | --- |
| Provider и языки | Не выбраны | Сеть не используется, пока профиль не заполнен и не запущен явно. |
| OCR engine / orientation | `Windows` / `Auto` | Горизонтальный системный OCR доступен без автоматического включения vertical path. Candidate crops в штатном pipeline всё равно распознаёт Tesseract. |
| Content layout | `DialogComic` | Использует проверенную ограниченную группировку и per-region overlay. `Book` и `StaticMenu` пока не реализованы. |
| Detector preset | `Standard` (`0.60`) | Экспериментальные китайские `0.65`/`0.70` включаются только вручную. |
| Candidate grouping | `Auto` | Применяет текущие bounded writing-system rules; ручные лимиты `1..12` нужны только для диагностики. |
| Фильтрация водяных знаков | Выключена | Включается вручную: Осторожная или Усиленная. |
| OCR preprocessing | Выключено | Не изменяет исходное изображение без явного выбора. Для обычного текста начните с `Light (1.25x)` или `Standard (1.5x)`. |
| Live timing | `Balanced` | Три подтверждения группировки/OCR с минимальным интервалом `250 ms` и polling `125 ms`. |
| Overlay mask | `Solid`, чёрный, opacity `1`, padding `0` | Предсказуемо закрывает исходный текст; padding подбирается в preview. |
| Debug overlay | Выключен | Не показывает диагностические рамки в обычной игре. |

### Фильтрация водяных знаков

На вкладке Распознавание настройка «Фильтрация водяных знаков» действует на все зоны профиля. Начальное значение — «Выключена», в том числе для старых профилей без этого поля. «Осторожная» требует более сильного сочетания признаков и сохраняет сомнительный текст. «Усиленная» может исключить детализированный цветной логотип с пониженным контрастом уже на первой странице.

Фильтр сочетает локальный контраст, структуру логотипа, повторяемость визуального рисунка на разных страницах и признаки адреса сайта. Адрес, цифры, бледность, цвет или положение в углу сами по себе не исключают текст. Повтор статичного кадра и возврат к уже известной странице не увеличивают счётчик. История ограничена текущей live-сессией и отдельной зоной; одноразовый запуск не накапливает страницы.

Исключённый кандидат не переводится и не получает маску overlay. Исходные пиксели не восстанавливаются и не удаляются; исходные OCR-блоки сохраняются для локальной диагностики. В live-отчёте поля WatermarkMode, WatermarkExcluded и WatermarkReasons показывают решение и признаки. Для контекстного анализа localContrast измеряет детали внутри текстурированных участков, а contextContrast сохраняет общий перепад яркости области: стык тёмного рисунка с белым полем не должен подменять контраст эмблемы. Контраст — оценка изображения, а не измеренная прозрачность.

Обучать приложение каждой эмблеме не нужно. Если OCR выделил только одну строку, фильтр дополнительно проверяет ограниченное окружение строки: границы небольшой области, распределение деталей и цвет. Если рамка значка слилась с фоном, проверяется также композиция соседних OCR-строк; их маски не объединяются. Это помогает находить фрагменты значка, а не только цельную эмблему. Знаки без отчётливых границ, очень крупные, монохромные или сильно искажённые эмблемы могут сохраниться; полезный текст со сложным декоративным оформлением может ошибочно исключаться в Усиленной. При таком результате выберите Осторожную или Выключена.

## 6. OCR engines, языки и packs

Экспериментальный Auto OCR использует выбранный набор моделей Tesseract. В окне выбора языков доступны поиск и отдельный список выбранных языков справа. Все выбранные пакеты должны быть установлены; отсутствие одного пакета вызывает понятную ошибку, а не незаметное распознавание неполным набором. В управлении пакетами можно установить весь доступный набор. Большее число моделей увеличивает затраты OCR и не гарантирует лучшей точности.

Автоматическое определение языка перевода включается отдельно. Оно сохраняет связный диалог и порядок строк, а пространственно независимые группы направляются переводчику с подходящим языковым признаком. Латиница и китайские иероглифы сами по себе не определяют конкретный язык. Ручной выбор языка остаётся доступен.

Для некоторых горизонтальных надписей с цветной обводкой предусмотрена ограниченная повторная обработка отдельных найденных строк. Она не меняет выбранный OCR-движок и не обращается к внешнему OCR. Поддерживаются только определённые признаки отделимых штрихов; декоративные шрифты, в том числе японские, могут по-прежнему распознаваться неправильно.

`Windows` предназначен прежде всего для горизонтального текста. `Tesseract` обязателен для vertical Japanese/Chinese и для распознавания candidate crops штатного pipeline. Vertical можно выбрать только для Japanese и simplified/traditional Chinese; для остальных языков UI принудительно оставляет Horizontal.

Текущий проверенный portable-набор содержит ровно:

- `eng` — English;
- `jpn` и `jpn_vert` — Japanese horizontal/vertical;
- `chi_sim` и `chi_sim_vert` — Simplified Chinese horizontal/vertical;
- `tha` — Thai.

Через кнопку `Управление языковыми пакетами OCR` во вкладке `Распознавание` доступны более широкие каталоги Windows OCR и Tesseract, но наличие языка в списке не означает, что он уже включён в конкретный portable.

- Для Windows OCR кнопка установки открывает системные языковые параметры. Установите OCR capability нужного языка, при необходимости выйдите из системы или перезагрузитесь, затем повторите `Проверить язык OCR`.
- Для Tesseract кнопка скачивает необходимые `*.traineddata` из официального `tessdata_fast` в папку `tessdata` рядом с приложением. Для vertical Japanese/Chinese требуются также соответствующие `_vert` packs.
- Не переименовывайте Google/Windows language tags (`th`, `ja`, `zh-CN`) в имена моделей Tesseract (`tha`, `jpn`, `chi_sim`) вручную: приложение выполняет это сопоставление отдельно.

## 7. Переводчики и секреты

| Provider | Назначение | Credentials |
| --- | --- | --- |
| `Google`, `Azure`, `Yandex` | Официальные API | Обязательны; секрет сохраняется только в Windows Credential Manager. |
| `GoogleWeb`, `BingWeb`, `YandexWeb` | Отдельно выбираемые экспериментальные/диагностические web-провайдеры | Не сохраняются. Доступность, throttling и формат ответа внешнего сервиса могут измениться. |

Автоматического переключения между провайдерами нет. Ошибка, timeout или HTTP `429` показываются как ошибка выбранного provider; приложение не заменяет его другим provider и не скрывает отказ результатом из другого маршрута. `WebAuto` и `glhf` удалены: старый профиль с таким значением нужно открыть и явно выбрать поддерживаемую замену.

## 8. Профили, overlay, кэш и горячие клавиши

Профиль хранит зоны, языки, OCR, переводчик и оформление overlay. Его можно создать, клонировать, импортировать и экспортировать как JSON. Сохранённые зоны не должны пересекаться; маска остаётся привязана к исходной геометрии, а рамка перевода может центрированно расширяться для читаемости.

Кэш перевода двухуровневый (memory + SQLite), TTL — 30 дней. Кнопка «Очистить кэш перевода» в разделе «Диагностика и отчёты» удаляет все сохранённые переводы из памяти и SQLite, включая непросроченные записи. Перед очисткой остановите live-перевод; профили и языковые модели не удаляются. Кэш проверяется перед сетевым запросом, но не используется как скрытая замена при отказе candidate runtime или провайдера.

Горячие клавиши по умолчанию:

- `Ctrl+Alt+T` — start/pause pipeline;
- `Ctrl+Shift+F8` — OCR preview;
- `Ctrl+Shift+F9` — собрать debug info;
- `Ctrl+Alt+O` — показать/скрыть overlay;
- `Ctrl+Alt+S` — показать настройки;
- `Ctrl+Alt+Q` — выйти.

Если сочетание занято другим приложением, статус регистрации покажет ошибку; измените конфликтующую комбинацию во вкладке `Настройки приложения`.

## 9. Диагностика

Начните с `Pipeline status`, статуса OCR pack и кнопки `Open live reports`. При start, stop и ключевых отказах live-сессия сохраняет локальный отчёт в:

**%LOCALAPPDATA%\GameTranslator\Diagnostics\Live**

Другие локальные данные:

- профили: **%LOCALAPPDATA%\GameTranslator\Profiles**;
- настройки/черновик: **%LOCALAPPDATA%\GameTranslator\State\settings.json**;
- SQLite-кэш: **%LOCALAPPDATA%\GameTranslator\Cache\translations.db**;
- Serilog: папка `logs` относительно каталога запуска приложения, обычно рядом с portable app.

Live/debug reports не загружаются автоматически, но могут содержать ограниченный OCR-текст, вход перевода и итоговый перевод. Перед передачей отчёта проверьте его вручную и удалите личный или защищённый контент. Credentials, raw HTTP responses и кадры экрана в штатный live report не записываются.

Практический порядок поиска ошибки:

1. Проверьте, что профиль сохранён, provider и оба языка выбраны, зоны корректны.
2. Повторите `Проверить язык OCR` для каждой используемой зоны.
3. Убедитесь, что detector имеет статус `Ready`; при `Unavailable` проверьте целостность полного portable runtime.
4. Выполните OCR preview: пустой результат указывает на язык, ориентацию, зону, масштаб или preprocessing.
5. Для provider failure смотрите вид ошибки, HTTP status и время следующей попытки в live report. Не запускайте параллельный fallback.
6. Остановите live перед копированием отчёта — `Stop live` сохраняет итоговую сводку.

## 10. Текущие ограничения

- Source-equivalent portable r44 собран и проверен только локально; transfer archive, подпись и GitHub Release ещё не подготовлены.
- Реализован только `DialogComic`; отдельные `Book` и `StaticMenu` policies требуют будущего решения и тестов.
- LTR owner-smoke и расширенная поддержка Brahmic/Indic, Hebrew и Arabic-derived scripts остаются отдельными открытыми задачами.
- Web-провайдеры зависят от внешних неофициальных endpoints и не считаются гарантированными release defaults.
- При отсутствии полного Paddle runtime штатный pipeline корректно останавливается в degraded-состоянии вместо ухудшения OCR через скрытый fallback.

Короткая строка из одной буквы внутри горизонтального абзаца на языке с пробелами может иметь квадратную или узкую рамку детектора. При тесном выравнивании со строками сверху и снизу она включается в тот же абзац; заданный пользователем предел строк по-прежнему действует. Исходные координаты строк сохраняются.

## Высота перевода и авторазмер (ADR-033)

В режиме Dialog / Comic рамка перевода сохраняет высоту исходного текстового блока, когда позволяют границы зоны и соседние реплики. Рамка центрируется на оригинале; при препятствиях размещение может измениться. Маска исходного текста сохраняет прежние размеры.

В настройках шрифта выбранной зоны флажок «Авторазмер (8–72)» включает подбор наибольшего размера, помещающегося в доступную рамку. Без флажка применяется заданный размер с существующим расширением области и уменьшением шрифта при нехватке места. Настройку нужно сохранить в профиле; старые профили открываются с выключенным авторазмером. В пределах диапазона 8–72 чрезмерно длинный перевод всё ещё может потребовать больше места.

Перевод переносится между словами. Если длинное слово не помещается, область расширяется или шрифт уменьшается; автоматические переносы по слогам с дефисами не добавляются. При расхождении фактической высоты отрисовки и расчёта дополнительное вписывание уменьшает текст до доступной рамки, сохраняя последнюю строку.

## Язык интерфейса

При запуске приложение использует язык интерфейса Windows: русский — русский интерфейс; английский и любой другой язык — английский интерфейс. После изменения языка Windows перезапустите приложение. Региональные форматы чисел и дат сохраняются. Названия пользовательских профилей и зон, распознанный текст и технические сообщения внешних сервисов не переводятся автоматически.

## Тестовый многоязычный OCR

Во вкладке «Распознавание» доступен выключенный по умолчанию переключатель «Auto — язык OCR». Выберите Tesseract, включите режим и раскройте «Языки для Auto OCR». Отметьте только языки страницы и сохраните профиль. Поле поиска фильтрует список по названию или коду языка; справа всегда видны выбранные языки. Снять флажок можно в любом из двух списков, поиск выбор не сбрасывает. Старые профили сохраняют прежний набор jpn+kor+chi_sim+eng. Для традиционного китайского выбирайте chi_tra, для упрощённого — chi_sim; лишние похожие языки могут ухудшать распознавание. Пустой набор блокирует запуск.

В разделе языковых пакетов кнопка «Скачать все языки Tesseract» последовательно устанавливает весь поддерживаемый каталог, включая вертикальные модели. Уже установленные файлы пропускаются. Можно остановить загрузку и запустить её снова; успешно установленные пакеты сохраняются. Статус показывает прогресс и число ошибок, подробности ошибок доступны в журнале. Загрузка не меняет выбранные языки Auto OCR. Для установки только выбранного набора используйте обычную кнопку установки языка OCR. При направлении «Авто» проверка и установка также учитывают вертикальные модели выбранных языков.

Во всех зонах временно используется выбранный набор Auto OCR вместо индивидуального языка OCR. Сохранённые языки профиля и зон не меняются и снова действуют после выключения режима. Направление письма определяется отдельно для каждого найденного текстового региона по разметке Tesseract, а не по углу поворота изображения. На коротких и неоднозначных областях автоматическое определение может ошибаться; ручной выбор остаётся доступным.

Во вкладке «Перевод» находится независимый переключатель «Auto — исходный язык перевода». Включённый Auto сохраняет компактные, выровненные строки реплики вместе, даже при смене письменности из-за имени или ошибки OCR. Пространственно отдельные фрагменты переводятся независимо через GoogleWeb, BingWeb или YandexWeb. Для выраженной каны/хангыля передаётся ja/ko; для неоднозначных иероглифов и латиницы — auto отдельно на каждую группу. Официальные API пока не поддерживаются этим переключателем. Выключенный Auto использует выбранный исходный язык, в том числе в BingWeb и YandexWeb. Ручное значение сохраняется при переключении и остаётся языком наследования OCR, если Auto OCR выключен. Для страницы со смешанными языками включите оба переключателя и сохраните профиль. Auto языка OCR, Auto исходного языка перевода и Auto направления текста — три отдельных настройки.

Старые экспериментальные профили без отдельного поля Auto перевода сохраняют прежнее автоматическое определение при загрузке; после сохранения оба переключателя независимы. Кэш разделяет ручной исходный язык и Auto. Диагностика записывает эффективный исходный язык перевода, сохранённый ручной язык и режим языка OCR. Границы отдельных областей детектора сохраняются. Близкие выровненные строки одной реплики могут объединяться при разной письменности; для такой смешанной группы остаётся auto. Перекрывающиеся OCR-рамки не должны переставлять строки. Геометрия не исправляет ошибки распознавания и не гарантирует разделение настоящих языков внутри тесно набранной реплики. Внутри смешанной строки разделение выполняется только при полном совпадении текста с уверенно распознанными словами одного прохода и достаточном промежутке между ними. При неполных координатах или неоднозначной границе строка остаётся целой. Имена и HP внутри японской фразы не разрезаются только из-за латиницы. Сырые OCR-координаты и маски сохраняются; перевод возвращается в исходном порядке. Диагностика TranslationSourceLanguages перечисляет языки групп в порядке TranslationInputText. Китайский и японский текст только из общих иероглифов надёжно разделить этим способом нельзя. Ручной исходный язык сохраняет прежнюю группировку.

Это многоязычное распознавание ограниченным набором моделей, а не универсальное определение языка: OSD Tesseract определяет письменность/ориентацию. Возможны ошибки на коротких фрагментах и смешанном тексте внутри одного блока; время OCR увеличивается. Описание возможностей: https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html .

При Auto OCR составной набор моделей учитывается при выборе правил группировки CJK; явное вертикальное направление сохраняется. Перед OCR горизонтальные строки сильно разного размера (высота отличается более чем вдвое) не объединяются в один участок. Это отделяет крупные заголовки от мелких подписей, но не исправляет ошибки распознавания стилизованных шрифтов.

После выбора направления Auto порядок строк перевода определяется фактическим направлением OCR в каждом участке: вертикальные колонки читаются справа налево, горизонтальные строки — сверху вниз. Это не гарантирует правильного определения направления или распознавания символов самим OCR.
