# Definition of Done + Quality Gates

Проект: Система экранного OCR-перевода игровых субтитров и текста для Windows 11

Версия: 1.1 (обновлено)

------------------------------------------------------------------------

# 1. Назначение документа

Критерии завершения задач, требования к качеству кода, обязательные проверки перед завершением спринта, минимальные требования к тестированию, критерии приемки модулей.

------------------------------------------------------------------------

# 2. Главный принцип

Задача считается выполненной, когда её результат соответствует согласованной цели, пройдены применимые к её риску проверки, а неприменимые Quality Gates явно отмечены как N/A с причиной.

------------------------------------------------------------------------

# 3. Общий Definition of Done

## Код
- Компилируется без ошибок.
- Нет временных заглушек TODO, отключённых блоков, закомментированных реализаций.

## Архитектура
- Соответствует MVVM, Clean Architecture.
- Использует Dependency Injection.
- Не нарушает модульность.

## Документация
- Обновлена архитектурная документация (при необходимости).
- Документированы новые или изменённые внешние контракты и настройки, когда это необходимо для их использования.
- Описаны новые настройки.

## Тестирование
- Тесты пропорциональны риску: для изменённой логики покрываются значимые успешные, ошибочные и граничные сценарии.
- Для ProfileValidator, CoordinateTransformer и CacheManager поддерживается не менее 80% юнит-покрытия при наличии измеряемого отчёта покрытия.

## Логирование
- Все ошибки логируются с понятным описанием.
- Пользователю показываются понятные восстановимые состояния захвата, OCR, языкового пакета, переводчика и overlay без технических деталей и секретов.

## Обработка исключений
- Нет пустых `catch { }`.
- Каждое исключение обработано или записано в лог.

------------------------------------------------------------------------

# 4. Quality Gates

Ниже приведён каталог Quality Gates, а не список, который механически выполняется для каждой правки. Для каждой задачи обязательны успешная сборка, отсутствие новых необоснованных предупреждений, проверка затронутых архитектурных границ и защита секретов. Остальные Gates выбираются по затронутому поведению; для производительности, интеграций и UI требуется проверка только при изменении соответствующего пути. Для релизной вехи выполняются все применимые Gates.

## QG1: Компиляция – 0 ошибок.

## QG2: Анализ предупреждений – нет новых предупреждений без обоснования.

## QG3: Архитектурная проверка – отсутствие циклических зависимостей, прямых зависимостей UI→Infrastructure.

## QG4: Тестирование – изменённое поведение имеет тесты, соразмерные риску. Для указанных модулей покрытие ≥80% при наличии отчёта.

## QG5: Производительность – для затронутых горячих путей измеряется CPU, RAM и время выполнения; рост нагрузки более 10% требует обоснования.

## QG6: Логирование – критические операции логируются.

## QG7: Работа с секретами – API-ключи не попали в JSON, SQLite, логи, настройки. Все секреты в Windows Credential Manager.

## QG8: Совместимость профилей – применяется при изменении профилей, настроек или схемы; старые профили открываются или мигрируют без потери данных.

## QG9: Проверка Overlay – применяется при изменении overlay: позиционирование, масштабирование, прозрачность, отсутствие мерцания.

## QG10: Проверка OCR – применяется при изменении OCR: получение текста, координат, bounding box.

## QG11: Проверка переводчиков – применяется при изменении переводчиков: успешный перевод и обработка ошибок API или неверного ключа.

## QG12: Проверка многозонности – применяется, когда изменение может повлиять на несколько зон или их независимость.

## QG13: Проверка кэша – применяется при изменении кэша или pipeline: повторный перевод берётся из кэша, учитывается TTL 30 дней.

## QG14: Проверка импорта/экспорта – применяется при изменении сериализации или профилей: данные не теряются.

## QG15: Проверка вертикального текста – применяется при изменении соответствующего пути: режимы Horizontal, Vertical, Auto через Tesseract по умолчанию.

## QG16: Проверка горячих клавиш – применяется при изменении регистрации, удаления или конфликтов.

## QG17: Проверка маскирования – применяется при изменении маски: оригинальный текст скрыт (solid/darken), настройки применяются.

## QG18: Проверка автообновления – применяется при изменении обновления: проверка, загрузка и установка не ломают приложение.

------------------------------------------------------------------------

# 5. Требования к коду

Имена: классы PascalCase, методы PascalCase, поля `_privateField`, интерфейсы `IInterfaceName`. Не допускаются неинформативные имена (Data1, Temp).

------------------------------------------------------------------------

# 6. Требования к комментариям

Комментировать только неочевидную логику. Очевидный код не комментировать.

------------------------------------------------------------------------

# 7. Требования к тестам

Каждый тест имеет понятное название, тестирует одну функцию, независим. Пример: `Translate_WhenTextExists_ReturnsTranslation`.

------------------------------------------------------------------------

# 8. Definition of Done для спринта

Спринт завершён, если выполнены его задачи, пройдены все применимые Quality Gates, обновлена необходимая документация и отсутствуют критические ошибки.

------------------------------------------------------------------------

# 9. Отчёт ИИ-агента после завершения задачи

Агент предоставляет: изменённые файлы, новые файлы, реализованные функции, тесты, известные ограничения, риски, статус Roadmap.

------------------------------------------------------------------------

# 10. Отчёт после завершения спринта

Процент готовности проекта, выполненные/невыполненные задачи, блокеры, техдолг, рекомендации на следующий спринт.

------------------------------------------------------------------------

# 11. Финальное правило

Если обязательный или применимый Quality Gate не пройден без принятого исключения, задача считается незавершённой, даже если функция визуально работает.
