# Независимое обновление областей меню

Статус: промежуточный план; первый этап реализован и проверен 2026-11-14.

Основание: владелец одобрил предложенную схему независимых областей и поручил зафиксировать план и приступить. Это разрешение на реализацию описанных этапов; каждый этап проверяется отдельно. Платформа, OCR-движки, публичные контракты, схема профилей и кэш переводов сохраняются.

Связанная задача: [#59](https://github.com/Dementius-cell/Game-Translator/issues/59); открытые зависимости проверены, конфликтов с задачей нет. Решение первого этапа принято в [ADR-038](../adr/README.md#adr-038).

Change Request: заменить обязательное повторное OCR-подтверждение неизменного переведённого фрагмента на независимое точное визуальное подтверждение с контрольным OCR. Польза — уменьшение очереди; риск — ложное сохранение текста при недостаточном сравнении. Поэтому первый этап сравнивает весь ограниченный crop и контекст, сохраняет source freshness и первоначальное OCR-подтверждение. Изменение локально для Application live StaticMenu, не требует миграции. Одобрение владельца получено в запросе начать этот план; повторное согласование не требуется.

## Проблема и цель

Live StaticMenu уже распознаёт отдельные detector crops, но повторно ставит неизменившиеся фрагменты в общую очередь. Подтверждение текста зависит от очередного OCR и истекает через две секунды. Цель — обновление одной области не должно запускать дорогой цикл для всех остальных или снимать их переводы при наличии свежего подтверждения неизменности.

## Этапы

1. **Независимое подтверждение неизменившихся фрагментов.** После первоначального подтверждения OCR сравнивать свежие пиксели с фиксированным образцом принятого OCR. Совпадение проверяется вместе с происхождением кадра, геометрией, detector members и контекстом распознавания. Оно может продлить существующее подтверждение, но не подтвердить новый текст или воскресить истёкший. Неизменившиеся области пропускают повторный OCR, кроме редкой контрольной проверки. Изменённые и неподтверждённые области идут существующим путём.
2. **Карта изменений до детектора.** Сравнивать небольшие плитки захваченной зоны; объединять только соседние изменения. Расширять области до границ существующих строк/блоков с запасом. Несвязанные изменения не превращать в один прямоугольник размером с экран. Добавить периодическую полную проверку и обработку смены страницы.
3. **Локальная детекция и согласование.** Детектор получает изменённые области; координаты возвращаются в исходную зону. Нетронутые кандидаты сохраняют идентичность. Удаление кандидатов ограничено действительно проверенной областью. Границы плиток не разрезают OCR-строки и абзацы.
4. **Приоритет и измерения.** Сохранять один последний ожидающий кадр на область и ограниченный общий параллелизм. Проверить справедливость очереди, задержку изменённой области, количество OCR/detector запусков и отсутствие влияния на соседей. Сравнение на сохранённых кадрах — отдельное локальное доказательство, не live-приёмка.

## Ограничения первого этапа

- Начать с точного сравнения ограниченного объёма пикселей; сходство фона/контуров не считать доказательством идентичности текста.
- Свежесть берётся из фактического source origin, а не времени доставки/обработки. Cached reuse, неизвестный источник, другой контекст и разрыв подтверждений не продлевают авторитет.
- Новые/пустые/ошибочные результаты, смена страницы, исчезновение, неоднозначная геометрия и потеря захвата сохраняют существующие правила.
- Контрольный OCR остаётся необходимым для исправления устойчивого ошибочного распознавания. Его результаты не подменяются визуальным предположением о тексте.
- DialogComic, one-shot, watermark-проекция, provider/cache semantics и ограничения памяти сохраняются.

## Проверка

- Синтетическое статичное меню: перевод живёт более двух секунд при новых одинаковых source frames, количество OCR существенно меньше количества обновлений.
- Изменение одной области: обновляется её перевод, соседние сохраняются и не запускают лишний OCR.
- Контрольный повторный OCR выполняется; изменившийся/пустой результат снимает старый перевод.
- Одинаковый cached frame, неизвестный origin, другой источник, остановка захвата и разрыв времени не сохраняют устаревший перевод.
- Поздний OCR/перевод старой версии не может восстановить снятый результат; подтверждение не выводится из одного OCR.
- Изменение геометрии, recognition context и пикселей вне разреженной выборки не скрывается оптимизацией.
- Release build, полный набор .NET tests, проверка документации. Live GPU/game smoke и фактический выигрыш задержки фиксируются отдельно от детерминированных тестов.

## Артефакты и статус

Этот документ — исходный документ плана для репозитория. Скриншоты, OCR-тексты, диагностические отчёты и результаты измерений остаются local-only ignored outputs в work; они не являются CI fixtures и не публикуются.

- Этап 1: реализован. Контрольный OCR через пять секунд от последнего принятого OCR source; точное сравнение каждого crop/context ограничено 131072 пикселями. Cached frames не продлевают подтверждение и не ставятся повторно в очередь после визуального наблюдения того же source.
- Этапы 2–4: следующие отдельные шаги после проверки первого этапа.

Проверки первого этапа: Release build — 0 предупреждений/ошибок; полный набор — 1507/1507 .NET tests. Новые [сценарии pipeline](../../tests/GameTranslator.Tests/Application/TranslationPipelineServiceIncrementalMenuTests.cs) проверяют независимость двух областей и редкий контрольный OCR с исправленным/пустым ответом. В статичном синтетическом сценарии 24 обновления требуют не более 8 OCR-вызовов, включая начальное подтверждение и аудиты. Это проверка числа операций, не измерение задержки настоящего OCR.

Сохранённые игровые кадры показали, что полное совпадение пикселей встречается редко на текстурном фоне. Этот этап не объявляется исправлением всех исчезновений и не подтверждает выигрыш real-game latency. Подробные числовые результаты сравнения остаются local-only ignored output в work. GPU/WPF/game endurance ещё не выполнен; release acceptance #30 остаётся открытой. Profile migration и provider/cache gates N/A: схема, поставщики и кэш не менялись. Application AGENTS обновлён из-за нового контракта визуального подтверждения.

Следующий шаг: карта локальных изменений и прототип ограниченной детекции с проверкой границ строк, корректного удаления кандидатов и поведения при анимации фона. Не ослаблять точную проверку текста ради увеличения процента пропусков OCR.
