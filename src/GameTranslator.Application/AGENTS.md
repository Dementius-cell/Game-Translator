# GameTranslator.Application AGENTS.md

These instructions apply to `src/GameTranslator.Application/**`.

## Purpose

Keep application use cases and contracts independent from concrete UI, platform, persistence, OCR, and translation implementations.

## Ownership

- Application services and orchestration.
- Ports and abstractions for capture, OCR, translation, cache, credentials, settings, profiles, hotkeys, debug, and updates.
- Translation pipeline behavior, timings, grouping, multi-zone handling, cancellation, and recoverable failures.
- Opt-in watermark candidate selection and bounded per-session/per-zone page evidence and bounded source-frame and neighboring OCR-line context for fragmented emblems; preserve raw OCR and source/revision authority, exclude only translation/overlay projection.
- Profile migrations and import/export orchestration.

## Local Contracts

- Application may depend on Domain and lightweight DI abstractions already accepted by the project.
- Do not add WPF, Windows API, SQLite, Tesseract, network SDK implementation, Credential Manager, file dialog, or UI framework dependencies here.
- Cache lookup remains part of normal translation flow before provider calls; the default TTL policy stays 30 days unless a Decision Record changes it.
- Keep OCR contracts engine-neutral. Windows OCR and Tesseract remain mandatory product capabilities implemented outside this layer.
- Keep translator contracts provider-neutral. Credentialed Google, Azure, and Yandex remain the supported provider set unless a Decision Record changes it.
- Resolve combined Tesseract model lists by their component writing systems. Bound horizontal candidate stacks by original detector-member heights (maximum 2:1) so large titles cannot absorb small captions through intermediate lines.
- Preserve raw OCR block geometry for diagnostics and masking; semantic grouping may create translation groups without destroying source geometry. Candidate requests may carry immutable crop-relative detector line hints; preprocessing must scale hints with pixels, and line coverage remains bounded numeric evidence rather than proof of OCR accuracy.
- With automatic translation source enabled, preserve compact aligned dialogue lines across script changes; a script change alone is not a translation boundary. Preserve detector-region identity in projected crop sources and never merge different detector regions. Spatially independent fragments can remain separate. Han/Latin remain language-ambiguous; explicit Japanese/Korean hints require substantial kana/Hangul. Split inside a line only with complete, confident word geometry from one recognition pass. Preserve raw masks and reading order; route/cache by each group's effective source language, then restore output order. Manual-source profiles retain their grouping behavior.

## Work Guidance

- An isolated horizontal menu rating row may be excluded from translation projection only with bounded source-pixel evidence of 3–5 separate filled five-point star silhouettes (>180 luminance, per-shape IoU>=.8 with the normalized star outline), comparable size, alignment and spacing. Require one detector line and one OCR block, crop height12–192, aspect2–6 and <=131072pixels. Preserve raw OCR, words, geometry and request/time metadata; no coordinate rules, OCR spelling blacklist or changes to freshness/confirmation. Letters, digits, punctuation, mixed labels, hollow/partial stars and unsupported routes must not be inferred as a rating from their text.

- Capture frames may carry immutable `Origin` metadata (source instance, compositor timestamp and actual source time) and `IsCachedReuse`. Preserve both through crop, scale, padding and recognition preparation. Legacy `CapturedAt` remains the delivery timestamp for compatible routes; it is not proof of a new source frame. Missing origin means unknown provenance, not an independently confirmed observation. These metadata alone do not establish capture liveness for a static source.

- `IRecentCaptureFrameSource` is an optional explicit freshness port, exposed by `CaptureService.CaptureRecentAsync`. Unsupported sources fail rather than silently use ordinary capture. Identity uses source ID/compositor timestamp; age uses `FreshnessTimestamp`, bounded by actual monotonic arrival when the compositor timestamp leads arrival. Cached delivery never refreshes either. Live StaticMenu candidates explicitly use this port; other capture routes remain ordinary.

- Live candidate capture failures are isolated to the zone whose capture failed. Continue capturing/reconciling the other zones; retain their OCR/text/translation authority. Remove the failed zone's candidates and pending work, emit CaptureFailed with its zone ID, and require fresh confirmation after recovery. When restoring a capture-hidden overlay, rebuild it from surviving states if any zone failed. Cancellation/disposal is not a recoverable zone failure: late capture success or failure must not restore an old session's overlay. Legacy full-page capture still propagates its failures.

- `MenuOcrScheduler<T>` runs live-menu OCR under the live-session authority. Supply monotonic times in the same domain as frame origins and complete each lease only after OCR actually terminates. Removed/cancelled generations retain their global slot until completion; pixel changes only replace the latest pending work. `MenuTextAuthority` separately checks source freshness, exact projected text confirmation and translation version. Keep the existing comic route independent.

- While a live session containing menu zones awaits capture or detection, service completed work under the same state authority, refill OCR slots and publish eligible results. A bounded 100 ms wake-up also checks expiry and start intervals without completion events. Do not create concurrent state writers or renew source age from processing time. Suppress publication during capture when the overlay is not excluded and capture restoration is enabled; restore the current result if work changed while hidden. Cancelled/disposed sessions must not publish or reconcile late stage results.

- With watermark filtering off, a newly captured menu frame may replace pending crops at recently detected bounds before detection completes. Preserve its actual origin; require the same source context and geometry evidence no older than 2 s. This starts recognition speculatively, not translation: keep at most one completed result per candidate and accept it only after same/newer-frame detector geometry matches. Disappearance retires the generation; unvalidated, stale or incompatible results cannot renew text authority. A fresh contradictory/empty OCR may immediately revoke old text, but never confirm its replacement before geometry validation. Capture does not count as a grouping observation. Avoid launching an older pending crop immediately before a synchronous fresh capture; retain cooperative progress while a capture actually waits. Watermark-enabled routes retain detector-derived crops and current evidence.

- `MenuGeometryMatcher` requires reciprocal uniqueness across the complete compatibility matrix, including exact bounds matches. Preserve fixed discovery anchors and member checks; never resolve ambiguity greedily by nearest distance or iteration order. Fresh same-version menu OCR renews authority without republishing identical presentation. Compare text/style, masks, debug content and placement constraints; ignore only the snapshot timestamp, and still publish confirmed geometry changes.

- Explicit horizontal menu with watermark off may retain a single-line track across bounded padding changes only when its fixed discovery signature and current signature have exactly the same absolute ink bounds and two-level glyph mask (luminance >96 and >128). Evidence requires unclipped, nonempty, nonsolid text-like extent, at most131072pixels; retain only bounds/hash, never the anchor frame. Keep IoU>=.75, edges<=.25*minHeight and reciprocal uniqueness. Never align/shift masks, update the anchor, infer OCR text or renew freshness from this evidence. Reconciliation and completed-OCR acceptance must use the same geometry rule; Auto/Vertical, grouped and watermark-enabled routes retain their prior rules.

- A separate bright glyph-core path under the same route restrictions may compare >210 cores inside >180 possible ink. Require exact absolute core bounds, symmetric containment (no core-to-background changes), at least64corepixels, at most15% uncertain ink, unclipped nonsolid text-like extent and at most131072crop pixels. Keep IoU>=.75 and edge changes<=.5*minHeight. Store only a private bounded trimmed mask against the immutable discovery anchor; no alignment, rolling anchor, frame retention or OCR/freshness inference. Preserve the exact-mask path above, reciprocal uniqueness, source identity and the shared reconciliation/completed-OCR acceptance rule.

- A core touching a detector crop edge requires independent border evidence from the exact source observation: nonnull identical origin, delivery/reuse metadata, mapped coordinates and identical crop bytes. Inspect an untruncated band of max(2,ceil(.05*height)) pixels, total expanded area<=131072, without selected neighbors. No >210 pixels may extend outside the crop; the outermost ring must contain no >180 pixels. Do not expand OCR, change detector bounds or synthesize missing pixels. Compute evidence separately for speculative OCR and detected regions, carry only the bounded mask into their respective acceptance checks, and never retain the full source frame for this purpose. Unknown provenance, actual clipped core, unavailable context and ambiguous neighbors retain the original rejection.

- ADR-036 StaticMenu Auto conservatively groups horizontal descriptions while keeping short elements and columns separate; explicit per-zone limits retain writing-system grouping. Preserve raw source geometry and never use owner fixture text as production rules. Menu numeric displays and complete standalone control hints are excluded only from translation projection; letters inside prose remain text. Explicit recognized key tokens may separate short action captions with complete word evidence, never wrapped prose. Keep source-bounded menu overlay, short CJK labels, output number/key integrity checks on cache hits, and mixed-mode independence. Do not add whole-menu context by concatenating independent labels or change cache/provider semantics.

- A tight first description line may join a shorter padded continuation only with bounded source-pixel evidence of comparable glyph height on a flat dark background. Keep original detector member rectangles, the 2:1 envelope limit and neighbor/column/gap guards; geometry-only grouping retains its existing font-size threshold. Reuse the existing recognition context after grouping, without text substitutions or extra OCR passes.

- A single horizontal menu line may use recognition context only when its aspect ratio is at least 12, bright source pixels cross its detector boundary, and the expanded outer edge is entirely quiet dark background. Reject context intersecting selected neighbors or containing ink on its outer edge. Preserve detector identity, source origin, mapped OCR coordinates and existing preprocessing/watermark exclusions; do not repair recognized words with substitutions.

- For such single lines, choose the largest clean margin from ceil(0.15 * line height) down to one pixel before recognition. Each smaller margin must independently satisfy the same neighbor, border and crossing checks. This is source-pixel selection, not repeated OCR. Multiline context keeps its existing single-margin behavior.

- Exclude misread standalone keycaps only from menu translation projection: require a detector-isolated compact light crop, one enclosed dark glyph and short Latin OCR. Keep raw text, words, geometry and source authority intact. Multiple glyphs, prose, whole-page requests and comic/vertical routes do not qualify. Do not turn observed misreads into a text blacklist; unresolved icons retain their existing behavior until independent evidence supports exclusion.

- Two-glyph trigger keycaps use separate bounded evidence: a bright silhouette with one stable side and one side tapering inward, plus two enclosed, aligned dark components. Rectangles, symmetric tapers, widening silhouettes and unsupported routes must remain untouched. A single trailing OCR punctuation mark is allowed only with this pixel evidence; it is never stripped from raw OCR or used as a global token rule.

- The existing exact standalone Space key hint also accepts SPACE. Keep whole-element matching and case-sensitive prose handling; do not exclude lowercase space, phrases containing SPACE or OCR misreads. Preserve raw blocks/words and comic projection.

- Model external effects as interfaces here and implement them in Infrastructure or UI services.
- Prefer explicit request/result types over loosely shaped dictionaries or stringly typed contracts.
- Keep async operations cancellable where the surrounding service already supports cancellation.
- Use deterministic clocks, options, and fakes in tests when cache, timing, expiration, or retry behavior is involved.

## Verification

- Live candidate detector unavailability is a per-zone failure in the returned batch and a non-blocking Degraded diagnostic state. Preserve healthy zones, retry on the next normal capture, and clear that zone's detector failure after an available response. Session counters are not worker restart counters; worker lifecycle remains separate telemetry.
- Live-menu recognition-only and prepared-translation passes neither consult nor populate the service-wide legacy frame optimization cache. Their authority lives in the session; translation cache lookup remains mandatory.
- Menu presentation equality compares final text/style, masks and debug output, excluding timestamps and already-resolved placement constraints. Suppress identical final snapshots only when the overlay is visible; an invalidated or moved result still publishes immediately. Preserve comic-only publication behavior.

- For application behavior changes, run focused Application tests and the architecture dependency tests.
- For pipeline, cache, OCR contract, translation contract, profile migration, or multi-zone changes, run the full test suite unless there is a documented reason not to.
